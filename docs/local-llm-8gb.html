Which local LLM fits an RTX 2000 Ada with 8 GB

This machine can run 3B–8B models entirely on the GPU at interactive speed. Larger models can still run by spilling part of the weights into the 64 GB of system RAM. For game NPC dialogue, an 8B model at 4-bit is the sweet spot, or 3–4B if the game renders on the same GPU.

Short answer

Will Llama work here?

Yes. Llama 3.1 8B Instruct at Q4_K_M is about 4.9 GB of weights. With an 8K-token context it needs roughly 6.3 GB in total, which leaves headroom inside 8 GB. Expect somewhere around 30–40 tokens per second, which is faster than people read.

Llama 3.2 3B needs about 3.2 GB and runs around twice as fast. That is the better choice if a game engine is using the same GPU.

Llama 3.3 70B does not fit. At 4-bit it is about 42 GB, so it would run almost entirely on the CPU at 1–2 tokens per second.

If by "llama" you meant the runtimes: llama.cpp and Ollama both run well on this card with CUDA.

What actually happened

With llama.cpp b11160, GPU prompt processing crashes with CUDA error: an illegal memory access once a batch exceeds 32 tokens. The CUDA 12.4, CUDA 13.4 and Vulkan builds all fail the same way. Short prompts work, and TinyLlama generated at 180 tokens/s before it failed. The pattern points at the NVIDIA driver (595.79) or the GPU, not the model. Until that is fixed, the game runs everything on the CPU. Rebooting and updating or rolling back the driver is the first thing to try.

Recommendation

What to use for NPCs

Default pick

Qwen3 8B or Llama 3.1 8B

Q4_K_M, 8K context, fully on the GPU. Good at staying in character, following a system prompt, and producing JSON for actions or emotions. Qwen3 is usually stronger at instruction following. Llama 3.1 has the larger fine-tune and role-play ecosystem.

Game on the same GPU

Qwen3 4B, Gemma 3 4B or Llama 3.2 3B

About 3–4 GB in total, which leaves around 4 GB for the renderer. Dialogue is simpler, but it is fast, and latency matters more than depth for background NPCs.

Quality ceiling

Qwen3 30B-A3B with expert offload

A mixture-of-experts model that activates only about 3B parameters per token. Keep attention layers on the GPU and put the expert layers in the 64 GB of RAM. It runs in the teens of tokens/s and writes noticeably better than 8B models. Use it for a single important character or offline content generation.

Runtime

How to run it

  • Ollama is the quickest way to start. One installer gives you a local REST API on port 11434, and it picks GPU layers automatically.
  • llama.cpp server is the better base for a game. It supports GBNF grammars and JSON schemas for guaranteed-valid NPC output, parallel slots so several NPCs can share one loaded model, KV cache quantization (-ctk q8_0) and fine-grained offload flags such as --n-cpu-moe.
  • LM Studio is a GUI for trying models side by side before choosing one.
  • vLLM is not recommended here. It targets Linux servers with more VRAM.
# Try it in two minutes with Ollama
ollama run llama3.1:8b
ollama run qwen3:8b

# Or llama.cpp server: all layers on GPU, 8K context, 4 NPC slots
llama-server -m Qwen3-8B-Q4_K_M.gguf -ngl 99 -c 8192 --parallel 4 -ctk q8_0 -ctv q8_0 -fa on
NPC-specific

Things that matter more than model choice

  • The game and the model share VRAM. A game engine can use 2–5 GB by itself. Budget for both before choosing the model size, or run the model on a separate machine.
  • Keep context short. Put persona, recent lines and a few retrieved memories in the prompt instead of full history. It saves VRAM and keeps time-to-first-token low.
  • Stream tokens so the dialogue box starts filling in under half a second.
  • Constrain output with a JSON schema or grammar ({"say": "...", "emotion": "...", "action": "..."}) so the game never has to parse free text.
  • Q4_K_M is the usual quality/size balance. Q5_K_M is slightly better if you have headroom. Below Q4, small models degrade quickly.
