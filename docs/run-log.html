Run it yourself

Three commands

install.bat

Checks for Node, downloads llama.cpp, and asks for a model set: Starter (~5 GB), Recommended (~31 GB) or Everything (~83 GB). Safe to re-run; downloads resume.

play.bat

Starts the server and opens the town at http://127.0.0.1:3000. The case setup opens straight away. Ctrl+C stops it.

play.bat --cli

The same game in the terminal. Pick a difficulty, read the briefing, type a villager's name to question them, /accuse when sure.

The server re-reads each villager's agent.md on every reply. For a murder, code decides the facts (victim, killer, where everyone really was, who lies) so the case is always solvable. The selected model then writes the story on top: weapon, motive, secrets, the clue at the scene.

Setup log

What happened, in order

  1. Checked the hardware

    nvidia-smi reported 8,188 MiB and 0 MiB in use; the Intel iGPU drives the display. No llama.cpp or Ollama installed.

  2. Found the model files

    Queried Hugging Face for 16 Q4 GGUF files from TinyLlama 1.1B to Qwen3 30B-A3B. All ungated, 82.6 GB total. Llama 3.3 70B left out: 42 GB, 1–2 tokens/s at best.

  3. First runtime download failed

    GitHub's "latest" release pointed at a v0.5.0 tag with no binaries. The script now picks the newest build that actually has the Windows CUDA zip (b11160).

  4. Sped up downloads

    One connection to Hugging Face gave about 3 MB/s. Splitting each file into 8 resumable ranges raised it to 5–8.6 MB/s, which appears to be the network's limit. All 16 finished.

  5. First reply was garbage

    TinyLlama loaded in 3 s and generated 220 tokens at 180 tokens/s, all of them escape characters.

  6. Traced it to the GPU

    Turning off flash attention fixed short prompts but hung on long ones. Other models crashed with CUDA error: an illegal memory access. The CUDA 12.4 and Vulkan builds failed too. CPU-only was correct.

  7. Added a GPU self-test with CPU fallback

    On first start the server runs a short llama-bench. If it fails, every model runs on the CPU. The result is cached for a week in data/device.json. Latest result: GPU self-test failed (hung for 20 s).

  8. Played it

    Tested the dialogue API on five models, generated three murder cases, ran scripted text-mode sessions, and took a headless screenshot of the browser town.

What I haven't checked

  • The browser game hasn't been played by hand. I only took one headless screenshot of the town. The auto-opening case setup, the briefing panel and the typing dots were never seen rendered.
  • Text mode was tested with scripted input, not typed in a real terminal. The animated dots were checked by simulating a terminal.
  • 11 of the 16 models, including every 12B–30B model, have never been loaded in the game.
  • The GPU path has never worked on this machine, so GPU speeds and the memory-fit estimates on the analysis page are untested.
  • No accusation has been made through the browser, so the win/lose screen and timeline table are unseen.
